# ClipVault Backend: Design Specification

**Date:** 2026-09-28  
**Project:** ClipVault (Smart URL & Bookmark Organizer)  
**Component:** Backend API & ADK Agent  
**Reference Architecture:** [recall_BE](https://github.com/Fuzailkazi/recall_BE)

---

## 1. Overview & Objectives

ClipVault is a smart bookmark organizer designed to solve the "200+ forgotten browser bookmarks" problem. Users paste any URL (articles, GitHub repositories, tools, tweets) with an optional note. The backend scrapes OpenGraph metadata, hands off the content to an AI Agent powered by Google's Agent Development Kit (`@google/adk`), generates a 2-sentence tl;dr summary and 3 relevant tags, classifies the category, and saves the bookmark to MongoDB.

Additionally, ClipVault provides a conversational Chat Mode allowing users to ask questions like *"Show me the bookmarks I saved last week about Docker"*, which the agent resolves by executing a `queryBookmarksByTag` tool against MongoDB.

### Architecture Principle
The backend development process, file organization, and endpoint patterns mirror [`recall_BE`](https://github.com/Fuzailkazi/recall_BE) directly, extended with a fast metadata scraper and a clean Single `LlmAgent` implementation.

## 3. Database Schema (`backend/src/db.ts`)

MongoDB connection is managed via Mongoose with two core models:

### 3.1 `UserModel`
```typescript
const UserSchema = new Schema({
  username: { type: String, unique: true, required: true },
  password: { type: String, required: true },
  createdAt: { type: Date, default: Date.now }
});
```

### 3.2 `BookmarkModel`
```typescript
const BookmarkSchema = new Schema({
  url: { type: String, required: true },
  title: { type: String, required: true },
  summary: { type: String, required: true }, // 2-sentence tl;dr generated by agent
  tags: [{ type: String }],                  // 3 hashtags, e.g. ["#devops", "#docker", "#cloud"]
  category: { type: String, required: true },// e.g. "devops", "frontend", "design", "ai", "tools"
  userNotes: { type: String },               // Optional note provided by the user
  ogImage: { type: String },                 // OpenGraph preview image URL
  userId: { type: mongoose.Types.ObjectId, ref: 'User', required: true },
  createdAt: { type: Date, default: Date.now }
});
```

## 4. Authentication & Security (`middleware.ts` & `override.d.ts`)

* **JWT Verification**: Follows the `userMiddleware` pattern from `recall_BE`:
  - Reads `req.headers['authorization']`.
  - Verifies token using `JWT_PASSWORD` from `config.ts`.
  - Attaches `req.userId = decoded.id`.
  - Rejects unauthorized requests with HTTP `403`.
* **Type Augmentation (`override.d.ts`)**:
  ```typescript
  export {};
  declare global {
    namespace Express {
      export interface Request {
        userId?: string;
      }
    }
  }
  ```

## 5. Metadata Scraper (`backend/src/scraper.ts`)

A lightweight, non-blocking scraper using native `fetch` and `cheerio`:
* **OpenGraph Tags**: Extracts `og:title`, `og:description`, `og:image`, falling back to standard `<title>` and `<meta name="description">`.
* **Body Text Snippet**: Cleans and extracts the first ~2,000 characters from `<article>`, `<main>`, or `<p>` tags.
* **Resilience**: If a website blocks crawling or returns an error, the scraper returns a fallback object containing the URL and hostname, allowing the agent to still classify and save based on the URL and user notes.

## 6. Single `LlmAgent` Architecture (`backend/src/agent.ts`)

We intentionally use a **Single `LlmAgent`** powered by `@google/adk` and Gemini (`gemini-2.5-flash` or `gemini-1.5-flash`), avoiding multi-agent orchestration overhead.

### 6.1 Tool 1: `saveBookmark`
Defined with a strict Zod schema:
```typescript
import { z } from 'zod';

export const SaveBookmarkSchema = z.object({
  url: z.string().url(),
  title: z.string().describe("Descriptive title of the page"),
  summary: z.string().describe("Clear, accurate 2-sentence summary of the webpage content"),
  tags: z.array(z.string()).length(3).describe("Exactly 3 relevant hashtags, e.g. ['#devops', '#docker', '#containers']"),
  category: z.string().describe("Primary category e.g. devops, frontend, backend, design, ai, tools, article")
});
```
* **Execution**:
  - The agent is prompted with the scraped page metadata and user notes.
  - The model generates the summary, 3 tags, and category, then triggers the `saveBookmark` tool.
  - The tool handler saves the document directly to MongoDB (`BookmarkModel.create({ ...args, ogImage, userNotes, userId })`).

### 6.2 Tool 2: `queryBookmarksByTag` (Chat Mode)
Defined with Zod schema:
```typescript
export const QueryBookmarksSchema = z.object({
  tag: z.string().optional().describe("Tag or hashtag to filter by, e.g. '#docker' or 'docker'"),
  searchTerm: z.string().optional().describe("Keyword search across title, summary, or category"),
  daysAgo: z.number().optional().describe("Filter bookmarks saved within N days (e.g. 7 for last week)")
});
```
* **Execution**:
  - When a user asks conversational questions (e.g. *"Show me the bookmarks I saved last week about Docker"*), the agent calls `queryBookmarksByTag`.
  - The tool queries MongoDB scoped strictly to `userId: req.userId` with date filtering and regex matching.
  - The retrieved documents are returned to the agent, which responds with a helpful conversational summary alongside the bookmark references.

## 7. Express API Endpoints (`backend/src/index.ts`)

All API routes follow the `/api/v1/` prefix:

### 7.1 `POST /api/v1/signup`
* **Input**: `{ "username": "...", "password": "..." }`
* **Action**: Hashes/stores new user in `UserModel`.
* **Output**: `201 Created` or `411 User already exists`.

### 7.2 `POST /api/v1/signin`
* **Input**: `{ "username": "...", "password": "..." }`
* **Action**: Verifies credentials and generates JWT.
* **Output**: `{ "token": "..." }` or `403 Incorrect credentials`.

### 7.3 `POST /api/v1/bookmarks` (Auth required)
* **Input**: `{ "url": "https://...", "notes": "optional user note" }`
* **Action**:
  1. Runs `scraper.ts` to get OpenGraph metadata and page text.
  2. Runs `LlmAgent` to analyze text, generate summary + 3 tags, and call `saveBookmark`.
  3. Writes document to MongoDB under `req.userId`.
* **Output**: `201 Created` with saved bookmark object.

### 7.4 `GET /api/v1/bookmarks` (Auth required)
* **Query Params**: `?tag=#docker&search=guide` (optional)
* **Action**: Fetches bookmarks belonging to `req.userId`, sorted by `createdAt: -1`.
* **Output**: `200 OK` `{ "bookmarks": [...] }`.

### 7.5 `DELETE /api/v1/bookmarks/:id` (Auth required)
* **Action**: Deletes bookmark matching `_id: id` and `userId: req.userId`.
* **Output**: `200 OK` `{ "message": "Bookmark deleted" }`.

### 7.6 `POST /api/v1/chat` (Auth required)
* **Input**: `{ "message": "Show me the bookmarks I saved last week about Docker" }`
* **Action**: Runs the `LlmAgent` with `queryBookmarksByTag` tool, returning conversational answer and matched bookmarks.
* **Output**: `200 OK` `{ "response": "...", "bookmarks": [...] }`.

## 8. Error Handling & Edge Cases

1. **Unreachable / Slow URLs**: Timeout on `fetch` after 5 seconds; scraper gracefully degrades to returning the raw URL and title so the agent can still complete the bookmark.
2. **Invalid JWT / Missing Token**: `userMiddleware` catches unauthenticated requests immediately and returns `403 Forbidden`.
3. **Database Connection Resilience**: `src/db.ts` handles Mongo connection errors and logs clear warnings.
4. **Agent Tool Failures**: If the LLM does not call the tool or fails validation, a deterministic fallback saves basic metadata with `#uncategorized`.
